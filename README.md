# Знову в ділі: рекомендаційна система апсайклінгу

Навчальний проєкт КПІ ім. Ігоря Сікорського, група ТВ-42, варіант 15. Дисципліна «Компоненти програмної інженерії ч.4. Якість та тестування програмного забезпечення».

Користувач позначає матеріали, які має вдома (пляшки, банки, старий одяг, картон...), а система пропонує вироби з покроковими майстер-класами. Ідеї можна фільтрувати за складністю, категорією та назвою. Можна додати, відредагувати або видалити власну ідею. Інтерфейс і контент доступні українською та англійською.

## Стек

| Частина | Технології |
|---|---|
| Бекенд | Node.js ≥ 22, Express 5, REST API, Swagger UI |
| База даних | SQLite (`better-sqlite3`), схема `server/db/schema.sql`, тестові дані `server/db/seed.sql` |
| Фронтенд | HTML + ванільний JavaScript (ES-модулі), Tailwind CSS v4, без фреймворків |
| Тести | Vitest (unit), supertest (API), Playwright (e2e), Postman-колекція |

## Швидкий старт

Потрібно: [Node.js](https://nodejs.org/) 22 або новіший (`node -v`) і Git.

```bash
git clone <url-репозиторію>
cd upcycling-app
npm install
npm start
```

Відкрийте http://localhost:3000. Документація API: http://localhost:3000/api/docs.

Під час першого запуску база `data/upcycling.db` створюється автоматично з `schema.sql` і `seed.sql` (25 ідей, 30 матеріалів, 12 інструментів). CSS збирається автоматично перед `npm start`.

## Запуск у Docker 

Потрібен лише [Docker Desktop](https://www.docker.com/products/docker-desktop/). Node.js на комп'ютері не потрібен.

```bash
docker compose up -d --build     # зібрати образ і запустити у фоні
```

Сайт буде доступний на порту **8080**: http://localhost:8080 на цьому комп'ютері, `http://<локальна-IP>:8080` для пристроїв у тій самій мережі. Щоб змінити порт, задайте `HOST_PORT` (PowerShell: `$env:HOST_PORT=9000; docker compose up -d`).

| Команда | Що робить |
|---|---|
| `docker compose ps` | Стан контейнера (має бути `healthy`) |
| `docker compose logs -f` | Логи сервера |
| `docker compose stop` / `docker compose start` | Зупинити / знову запустити (дані зберігаються) |
| `docker compose up -d --build` | Оновити контейнер після змін у коді (дані зберігаються) |
| `docker compose down -v` | Видалити контейнер **разом із даними**: усі додані ідеї та фото зникнуть, наступний запуск почнеться з еталонних seed-даних |

База й завантажені фото зберігаються в Docker-томах `upcycling-data` і `upcycling-uploads`, тож перезапуск і перезбірка їх не стирають.

## Змінні середовища (необов'язкові)

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `DB_PATH` | `data/upcycling.db` | Файл бази SQLite |
| `UPLOAD_DIR` | `uploads` | Тека для завантажених фото |
| `RATE_LIMIT` | `100` | Ліміт запитів на запис (POST/PUT/DELETE) з однієї IP за 15 хв; `off` вимикає ліміт |

У PowerShell: `$env:PORT=4000; npm start`. У bash: `PORT=4000 npm start`.

## Як працює рекомендаційний алгоритм

Користувач вибирає матеріали. Для кожної ідеї система перевіряє обов'язкові та необов'язкові матеріали:

| Ситуація | Результат |
|---|---|
| Бракує хоча б одного **обов'язкового** матеріалу | ідея не показується |
| Є всі матеріали | **повний збіг** (`full`) |
| Бракує рівно одного **необов'язкового** | **частковий збіг** (`partial`), показується, чого бракує |
| Бракує двох і більше необов'язкових | ідея не показується |

Порядок результатів: спершу повні збіги, потім часткові. Далі за вибраним сортуванням (складність, час, новизна), а за рівності за id. Якщо матеріали не вибрано, показується весь каталог з урахуванням інших фільтрів.

## API 

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/api/materials?lang=uk` | Список матеріалів |
| GET | `/api/tools?lang=uk` | Список інструментів |
| GET | `/api/ideas?materials=1,4&difficulty=easy,medium&category=garden&q=банка&sort=difficulty_asc&lang=uk` | Каталог і рекомендації |
| GET | `/api/ideas/{id}` | Майстер-клас (матеріали, інструменти, кроки) |
| POST | `/api/ideas` | Нова ідея (`multipart/form-data`, фото обов'язкове) |
| PUT | `/api/ideas/{id}` | Редагування (фото необов'язкове) |
| DELETE | `/api/ideas/{id}` | Видалення |

Повний контракт описано в `server/docs/openapi.yaml` і на сторінці `/api/docs`. Помилки завжди мають формат `{ "error": { "code", "message", "details" } }`. Postman-колекція лежить у теці `postman/`.

```

                   validation/ (zod), middleware/ (завантаження фото, помилки), db/ (схема, seed), docs/ (OpenAPI)
public/            фронтенд: index.html (каталог), idea.html (майстер-клас), idea-form.html (форма),
                   js/ (api, i18n, сторінки), locales/ (uk.json, en.json), images/seed/ (фото seed-ідей)
src/styles/        вихідний CSS для Tailwind (дизайн-токени)
tests/             unit/, api/, e2e/
postman/           Postman-колекція
uploads/           фото, завантажені користувачами (не в git)
data/              файл бази даних (не в git)
```
